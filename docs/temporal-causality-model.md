# Temporal Causality Model

## 1. Purpose

Temporal order is necessary for causal history,
but temporal order alone is not causality.

The Temporal Causality Model defines how an AI agent system
may bind:

- prior state,
- available evidence,
- evaluation,
- decision,
- action,
- observed outcome,

into an auditable causal path.

---

## 2. Core Distinction

The following sequence:

```text
A
↓
B
↓
C

only establishes order.

It does not prove:

A caused B
B caused C

The Temporal Causality Binding layer therefore requires
explicit causal bindings.

State
  │
  │ causal binding
  ▼
Evaluation
  │
  │ causal binding
  ▼
Decision
  │
  │ execution binding
  ▼
Action
  │
  ▼
Outcome
3. Decision-Time Reality

A causal account of a decision must preserve
what the agent actually had access to at decision time.

The system distinguishes:

available
accessible but unused
used
unavailable
unknown
discovered later

This distinction prevents later knowledge
from being injected into earlier decisions.

4. Temporal Illusion

Temporal Illusion occurs when a later explanation
is presented as though it were the actual runtime cause.

Example:

Runtime:

State A
↓
Decision B
↓
Action C


Later discovery:

Evidence X

An invalid reconstruction would be:

Evidence X
↓
Decision B

when Evidence X was not available at the time
Decision B occurred.

The correct representation is:

State A
↓
Decision B
↓
Action C

Later:
Evidence X
↓
Retrospective Analysis
↓
New Causal Claim

The historical decision context remains unchanged.

5. Causal Strength

Not all causal relations are identical.

The protocol distinguishes:

direct cause,
contributing cause,
enabling condition,
constraining condition,
authorizing condition,
triggering event,
routing influence,
timing influence,
inhibiting cause,
counterfactual dependency,
disputed causality.

This prevents every earlier condition
from being flattened into a generic cause.

6. Counterfactual Support

A causal claim may be strengthened by asking:

What would happen if this predecessor were removed or changed?

Supported methods include:

intervention,
replay,
comparison,
simulation,
human analysis.

Counterfactual support strengthens causal analysis,
but method and assumptions must remain visible.

Simulation alone is not proof of runtime causality.

7. Causal Paths

A causal path connects multiple bindings.

Pulse
↓
State
↓
Evaluation
↓
Decision
↓
Action
↓
Outcome

Each arrow is an independent claim.

A path may be:

candidate,
supported,
verified,
disputed,
incomplete,
rejected.

Missing links must remain visible.

The protocol does not permit a plausible narrative
to silently fill causal gaps.

8. Competing Explanations

Multiple causal paths may coexist.

Path A:
State Risk
↓
Decision
↓
Action


Path B:
External Event
↓
Decision
↓
Action

The system may preserve both until sufficient evidence,
counterfactual support, or review resolves the dispute.

This is preferable to forcing one premature explanation.

9. Relationship to Structural Precedence

Structural Precedence answers:

What is prior to what?

Temporal Causality Binding asks:

Did that prior condition actually influence
this later decision or action?

Therefore:

Precedence
≠
Causality

but:

Valid runtime causality
requires compatible precedence direction.
10. Relationship to Adaptive Cadence

Adaptive Cadence decides:

When should the system evaluate again?

Temporal Causality Binding records:

What caused that timing decision?

Example:

Risk Increase
↓
Cadence Evaluation
↓
Accelerate
↓
Earlier Next Pulse

This makes timing itself auditable.

11. Principle

A history is not causal merely because it can be narrated in order.

A trustworthy temporal agent must preserve:

what existed,
what was available,
what was used,
what influenced the decision,
what produced the action,
what followed,
and what remains uncertain.
